# 빠듯한 일정 경고 — 설계 (짧은 버전)

## 왜
여행 일정을 짤 때 "11:00 카페 → 11:20 식당"처럼 이동 시간이 모자란 걸 미리 알아채고 싶다.
앱은 이미 지도 탭에서 장소 사이 이동 시간을 계산하고 있으니, 그걸 목록 화면 경고로 쓴다.

## 목표 / 하지 않을 것
- 목표: 목록에서 붙어 있는 두 일정 사이에 이동이 안 되면 경고 한 줄.
- 하지 않음: 머무는 시간 계산(일정엔 시작 시간만 있음), 일정마다 이동 수단 입력, "여유 있음" 표시.
- 실패로 볼 것: 걸어서 3분 거리에 경고가 뜨는 등 믿을 수 없는 경고. 경고가 떴으면 진짜 빠듯해야 한다.

## 정한 것 (사용자)
- 판단 기준 **A**: 이동 시간만 본다. `이동 시간 > 다음 일정 시각 − 이번 일정 시각`이면 경고.
- 이동 수단 **A**: 도보·대중교통 둘 다 계산하고 **빠른 쪽** 기준.

## 고려한 방법
- 판단: A 이동 시간만(선택) / B 모두 같은 최소 머무는 시간 더하기 / C 일정마다 머무는 시간 입력.
  A는 가장 단순하고 입력이 그대로. 머무를 시간이 없는 경우는 못 잡는다.
- 이동 수단: A 빠른 쪽(선택, 계산 2번이지만 폰에 저장) / B 대중교통만(짧은 거리에 헛경고) / C 일정마다 선택(입력 늘어남).

## 모습
```
┌ 11:00  카페 ┐
  ⚠️ 20분 뒤 다음 일정인데 이동이 35분 걸려요 (대중교통 35분 · 도보 42분)
┌ 11:20  라멘집 ┐
```

## 동작 (내가 정한 부분)
- 비교 대상: 목록에 보이는 순서로 **바로 붙어 있는** 두 일정. 둘 다 시간과 장소(lat/lng)가 있어야 함.
  하나라도 없으면 그 쌍은 건너뜀(장소 없는 일정 너머로 이어 비교하지 않음).
- 다음 일정 시각이 앞 일정보다 이르거나 같으면 비교하지 않음(순서를 일부러 바꾼 것일 수 있음).
- 계산: `src/lib/routes.ts`의 `getLeg`를 그대로 사용(도보, 대중교통 각각). 대중교통 출발 = 앞 일정 시각(`transitDeparture`).
  지금 보고 있는 날짜만 계산. 결과는 기존 경로 저장본(localStorage)으로 재사용.
- 경로를 못 구하면(오프라인·실패) 그 수단은 빼고 판단, 둘 다 못 구하면 경고 없음.
- 지도 탭은 건드리지 않음(이미 이동 시간을 보여줌).

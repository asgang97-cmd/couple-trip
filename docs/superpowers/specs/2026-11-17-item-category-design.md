# 일정 종류(카테고리) — 설계

## 왜
일정마다 종류(숙소·교통·식사·관광·쇼핑·기타)를 붙여서, 목록 카드에서 한눈에 알아보고, **여행 전체에서** 한 종류만 모아 볼 수 있게 한다("우리 어디서 먹기로 했지?"를 한 번에).

## 목표 / 하지 않음
- 목표: 일정 넣을 때 종류 고르기, 목록 카드에 종류 아이콘, 목록 탭 위 종류 버튼으로 여행 전체 모아 보기.
- 하지 않음: 지도 핀 색·아이콘, 비용을 종류별로 합치기, 가계부와 연결, 구글 장소 정보로 종류 자동 추천, 종류 직접 만들기.
- 실패로 볼 것: 종류를 안 고르면 저장이 안 되는 것, 예전 일정에 아이콘이 잔뜩 붙어 지저분해지는 것, 모아 보기에서 여행 기간 밖(숨은) 일정이 나오는 것.

## 방법 (고른 것: A)
- **A. 목록 탭 위 종류 버튼 줄 (고름)**: `전체 · 🏨숙소 · 🚃교통 · 🍜식사 · ⛩️관광 · 🛍️쇼핑 · 📌기타`. 전체 = 지금처럼 날짜 탭 + 그날 일정, 종류 고르면 날짜 탭 대신 여행 전체의 그 종류 일정. 탭 수 그대로, 보던 자리에서 바로 전환.
- B. "모아보기" 탭 추가: 아래 탭이 6개가 돼 폰에서 좁아지고, 탭을 옮겨야 해서 뺌.
- 모아 보기 범위: 그날 안에서만 고르기(①)는 하루 일정이 5~8개라 효과가 작아서 사용자가 여행 전체(②)를 고름.

## 정한 것
- 종류 6개 (저장 값 → 이름 · 아이콘): `stay` 숙소 🏨, `move` 교통 🚃, `food` 식사 🍜, `sight` 관광 ⛩️, `shop` 쇼핑 🛍️, `etc` 기타 📌.
- 저장: items에 `category text` 칸 추가(새 SQL `009_item_category.sql`), 6개 값 또는 비어 있음(null)만 허용.
- **종류는 골라도 되고 안 골라도 됨**(null). 예전 일정은 모두 null.
  - null이면 카드에 아이콘 없음(예전 일정이 갑자기 📌투성이가 되지 않게).
  - 모아 보기의 **기타**에는 `etc`와 종류 없는 일정이 같이 나옴(어디에도 안 빠지게).
- 일정 창: 장소 이름 칸 아래 "종류" 버튼 6개 한 줄(누르면 고름, 고른 걸 다시 누르면 해제). 수정할 때는 저장된 종류가 골라져 있음.
- 카드: 시간 옆에 아이콘(화면 읽기용 이름은 "식사" 등).
- 모아 보기 화면:
  - 여행 기간 안 일정만(지금 목록과 같은 기준), 날짜 → 시간(없으면 그날 뒤) → 원래 순서.
  - 날짜가 바뀔 때마다 작은 제목 `1일차 · 1/12(화)`.
  - 카드는 지금 카드 그대로(하트·댓글·수정 동작 같음). 일정 사이 "빠듯한 일정" 경고와 날씨는 날짜별 화면에만.
  - 하나도 없으면 `아직 식사 일정이 없어요`.
  - 이 화면에서 "일정 추가"를 누르면 그 종류가 미리 골라진 채 열림(날짜는 지금 보던 날).
- 고른 종류는 이 폰에서만, 앱을 다시 열면 `전체`.
- 순서: **SQL을 먼저 실행한 뒤 배포**(칸이 없으면 저장이 실패함). 실행 안내는 README와 대화에서 한 단계씩.

## 만드는 쪽에 맡기는 것
- 버튼 줄이 폰 폭을 넘으면 가로로 밀어 보기(줄바꿈 아님), 고른 버튼 표시 방식은 기존 토큰·`aria-pressed`로.
- 종류 목록·아이콘·이름은 한 파일(`src/lib/category.ts`)에 모아 둘 것.

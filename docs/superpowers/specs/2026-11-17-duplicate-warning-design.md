# 중복 알림 (일정·준비물) — 짧은 설계

## 왜
둘이 따로 일정·준비물을 넣다 보면 상대가 이미 넣은 걸 못 보고 또 넣는다. 저장하는 순간 "이미 있어요"라고 알려 준다. **막지는 않는다**(호텔처럼 일부러 여러 번 넣는 일정이 있음).

## 목표 / 하지 않음
- 목표: 일정 저장, 준비물 추가 순간에 겹치는 게 있으면 확인 창 → [취소]면 저장 안 함(쓴 내용 그대로), [확인]이면 그대로 저장.
- 하지 않음: 서버에서 막기, 목록에 '겹침' 표시, 둘이 동시에 넣은 경우 잡기, 준비물 '챙길 사람'을 바꿀 때 알림, "추천 준비물 한 번에 넣기"(지금처럼 이미 있는 이름은 조용히 뺌).
- 실패로 볼 것: 겹치지 않는데 창이 뜨는 것(특히 일정 수정할 때마다), 저장이 막히는 것.

## 방법 (고른 것: A)
- **A. 저장할 때 확인 창 (고름)**: 폰에 이미 불러온 목록과 비교. 서버 변경 없음, 오프라인에서도 동작. 동시에 넣는 경우는 못 잡음(드묾).
- B. 목록에 '겹침' 표시: 동시 입력·예전 중복까지 보이지만 저장 순간엔 조용하고, 일부러 반복한 일정에 표시가 계속 남음.
- 서버에서 막기: "막지 말 것"과 반대라 제외.

## 일정
- **같은 장소**: 둘 다 구글 장소 번호가 있으면 번호가 같을 때. 하나라도 없으면 장소 이름이 같을 때(앞뒤·중간 공백, 영문 대소문자 무시). 장소 이름이 빈 일정은 비교 안 함.
- 여행 전체(모든 날짜)에서 찾음. 수정 중인 일정 자신은 뺌.
- 수정할 때는 **장소를 바꿨을 때만**(장소 번호 또는 이름이 처음과 다를 때) 확인. 원래부터 겹치던 일정을 메모만 고칠 때는 안 뜸.
- 창 문구(폰 기본 확인 창, 앱의 다른 확인 창과 같은 방식):
  ```
  이미 넣은 장소예요
  · 2일차 11/30(월) 14:00 센소지 (밍하)
  그래도 저장할까요?
  ```
  겹치는 일정이 여러 개면 최대 3개까지, 시간 없으면 시간 빼고. 괄호 안은 넣은 사람.

## 준비물
- **같은 이름**: 공백·영문 대소문자 무시. 챙긴(체크한) 것도 포함.
- 새로 넣는 게 **같이**: 같은 이름이 누구 것이든 있으면 확인.
- 새로 넣는 게 **밍석/밍하**: 같은 이름이 **같이** 또는 **같은 사람** 것으로 있으면 확인. 상대 사람 것만 있으면 조용히 넣음(여권은 각자).
  - 사용자가 말한 건 "같이 준비하기로 한 것"의 중복. 같은 사람이 자기 것을 두 번 넣는 것도 알리는 건 내 판단(그것도 실수일 가능성이 높아서).
- 창 문구: `"여권"은 이미 있어요 (같이). 그래도 넣을까요?` (받침 없으면 `는`: "카메라"는)

## 만드는 쪽에 맡기는 것
- 비교 함수는 `src/lib`에 순수 함수로(테스트 쉽게), 창은 ItemForm 저장·PackingList 추가에서 `confirm()`.
